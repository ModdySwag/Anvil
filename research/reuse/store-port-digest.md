## 0. What the store surface is, and what Anvil wants from it

- Header (L1-16): "the pack storage layer (sound banks + pattern packs)". Two install classes in ONE store and one storage layer: `strudel` `.pfpack.json` (pattern packs for the code drawer) and `synth` `.pfsynth.json` (patch banks for the SYNTH desk; a bank may also carry patterns — chip `both`). "packs are DOWNLOADED, never streamed."
- Storage law (L9-12): "IndexedDB is the durable home (audio-friendly, no 5 MB localStorage cap). The old localStorage map (forge-packs) is migrated once and then retired; a browser without IndexedDB (some file:// setups) falls back to localStorage, and with no storage at all, to memory — each state is reportable, so the UI can be honest (`pfPacksBackend` returns `'idb' | 'ls' | 'mem'`)."
- Quota law (L14-16): "`pfPacksPut` resolves `{ ok:false, error:'quota' }` when the browser refuses the write, and NOTHING is recorded as installed in that case — the old code toasted 'installed' while `savePacks()` silently swallowed the quota error."
- Anvil target (pinned): `_p5_wave.md §4` — "Store core (`src/av_store.js` — fetch manifest, verify sha256, IDB install `av-packs-store`, quota-honest, offline re-launch) · store card UI (`src/av_store_ui.js`) + `verify/cdp_store.mjs` (parent-run) · … synth-card BANK select + ONE shared apply core (bank → `avApplyParam` path application) · preview audition (client-side OfflineAudioContext v1) · `index.json` manifest for the packs dir. Hosting/deploy = the final wave; the store must work locally from `file://` + the test harness." Pack format pinned in `_p5_wave.md §1` (`.avbank.json`, flat `avApplyParam` path→value `patch` maps, optional `seq`).
- Shape of the port: the storage/honesty layer (app_store.js) is close to a straight ADAPT; the UI layer (sidebar markup in app_ui.js) is a re-skin ADAPT onto Anvil's card language; the bank-select/apply flow is the one real semantic difference (PF applies a `{voice, def}` object; Anvil applies a flat path map through the existing funnel).

### 1.3 IDB install flow (end to end)

1. Card INSTALL click → `pf.packsInstall(id)` (app_ui.js:146) — `setPackStatus('installing:'+id)` + re-render; lookup `packIndex.packs.find(p => p.id === id)` (L148-150).
2. `fetch(packIndex.base + meta.file)` with a **30 s `AbortController`** (L152-155); non-OK throws (L156).
3. `arrayBuffer` → `crypto.subtle.digest('SHA-256', buf)` → hex compared to `meta.sha256`; mismatch throws `'checksum mismatch'` (L158-161). **sha is verified in-browser, per install, before anything is stored.**
4. `JSON.parse` + class gate: must carry `patterns` or `patches` arrays or it is a `'bad pack file'` (L162-163).
5. `pfPacksPut(pk, {id, file, sha256: hex, size: buf.byteLength})` (L165) → `app_store.js:247-288`: `'bad-pack'` / `'no-id'` (slug regex L250) → stored record (adds `kind` + `meta{file,sha256,size,at}` L251-260) → IDB `put` (L261-271) → `installedPacks[id] = stored` → resolves `{ok:true, backend, tables}`.
6. Any `!res.ok` → specific toast: quota → "Browser storage is full — remove a pack, then install again"; otherwise "Pack could not be stored (<error>)" (L166-167). **A pack that cannot persist is NOT shown as installed.**
7. Success → toast `'Sound bank installed: ' | 'Pack installed: ' + name + (patches · patterns)` + `'— this session only: no browser storage available'` when backend is `mem` (L169-173); `pfSynBankPaint()` (L174).
8. Download failure (network/abort) → "Pack download failed — check the connection to moddys.net" (L177); `setPackStatus('ready')` + re-render (L179).
- Uninstall L181-199/292-305: storage drop first; memory follows only on a successful drop; a degradation-session removal goes to `pfPacksDroppedNoDb` and is written through at adoption (L299-301).

### 1.4 Quota handling

- IDB write failure names are **distinguished** (L266-271): `InvalidStateError`/`TransactionInactiveError` ("a closed connection (tab churn) may heal on the next call; a quota will not — say which") → one reopen-and-retry; `QuotaExceededError` → `error:'quota'`; else `'idb:<name>'`.
- localStorage tier L273-287: `setItem` throw → `QuotaExceededError` → `{ok:false, error:'quota', backend:'ls'}`; any other failure → in-memory `{ok:true, backend:'mem', volatile:true}` (the UI's "this session only" toast).
- Estimate/reporting: `pfPacksEstimate` L307-314 + storage line app_ui.js:2122-2129; hydration keeps the backend string honest (`'ls'` promoted from `'mem'` only when an actual LS write lands, L278-279).
- The contract to port verbatim: **put resolves before the UI claims anything; the failure name decides the toast; nothing durable → not "installed".**
